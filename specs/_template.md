> 本模板规定 `specs/NNN-short-name.md` 的推荐结构与最低内容要求。**不得以模板代替具体规格的审批**：每个具体 SDD 必须填写实质内容后才可提交 `@plan-reviewer` 评审。

## 使用规则

1. 复制本模板为 `specs/NNN-short-name.md`，三位编号与 PRD 编号对应，短英文主题名与 PRD 一致。
2. 填写时删除各节的「填写指引」提示，保留章节骨架与编号。
3. `Status` 初始必须为 `Draft`；只有 `@plan-reviewer` 返回 `APPROVED` 且用户明确批准后才可改为 `Approved`（见 `specs/README.md` 门禁）。
4. 需求使用编号 `REQ-1..N`，与 PRD 的 `AC-1..N` 一一对应；允许有依据的子条款（`REQ-x.y`），每个子条款须说明理由。
5. 必须包含：AC → REQ 映射、REQ → 命名测试映射（穷举）、任务拆分（红-绿-重构）、待核验／未决事项清单。
6. 所有外部事实（法例条文、官方参数、生效日期、第三方行为、官方示例数值）必须标注「待核验」直至有官方证据；不得虚构参数、公式、生效状态或测试预期值。
7. 修改已 `Approved` 或 `Implemented` 的规格属于变更请求，须重走受影响的审批与验证门禁。
8. 引用 PRD 锚点（章节／AC 编号）而不是整段复制 PRD 文本。
