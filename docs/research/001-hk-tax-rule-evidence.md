## 0. 证据分层与使用规则（Provenance 摘要）

**层级定义（全文强制区分，禁止混层）：**
- **T1 直接一手（Primary direct）**：有 parent 亲自核验记录（直接抓取页面/PDF/内联 JS 原文并核对锚点，或逐题通读官方页提取全文并留记录；须注明提取方式，无 raw hash 不构成降级）；本文件“1.x 已核实/已核/observed”均指 T1。仍不等于法例逐条核验或官方认证。**T1 子类**：① T1（PDF/HTML 直抓）；② T1-observed（官方计算器行为）；③ **T1-现行法例文本**（电子版香港法例现行整合本，parent 直读 2026-10-08 版面；动态页面无 raw hash；引文以条文号为准，见 1.17）。
- **T2 次级研究（Secondary research）**：parent 抓取官方页的 Tavily 提取或研究者报告，带 URL/锚点线索，但**无 parent 核验记录**（本批新增见 1.12–1.16）；**一律候选**，不得进入 fixture 或规则数据；**无 parent 直读核验记录不得升 T1**。
- **T3 算术检查（Arithmetic check）**：对给定数字的独立算账；仅用于发现矛盾或确认自洽，**不是法律证据，也不是 fixture 批准**。
- **受阻/不一致（Blocked）**：来源冲突、算术矛盾或证据缺失；不得用“仅告警”关闭缺口。

**状态规则：**
- “预算公布 / 通过 / 刊宪 / 生效 / 过渡”是不同状态；提案措辞不得当作生效规则。
- FAQ 只能证明官方所载示例或 entitlement 表述，不能单独证明立法状态、资格语义或完整取整步骤。
- 引用必须带 **URL + 锚点（FAQ 题号、章节、条例/文件编号）+ 文书日期或年度**。
- 单日生效的**具体时刻**是元数据；是否需要文书时刻取决于**母法过渡条款**是否按时刻保留旧制。2025-02-26（11:00 生效）与 2026-02-26（当日生效）的 Cap.117 s78／s79 均按**日期**保留旧制（旧文书／之前订立的同双方同条款协议／符合旧协议的转易契），故普通文书仅凭日期即可；不得以缺时刻 blanket 拒算（见 1.9/B11）。
- 2026-10-07 **Oracle 证据政策**（估算器取整证据、Gate 2 条件、红测与 reference harness 边界）见 7.1；不修改已批准需求。
- **负面发现（取整，2026-10-08）**：Cap.112 现行整合本全文检索 `nearest`＝0 命中，`cent(s)/fraction` 命中均为无关词 → **无税额取整条款**；最终税额取整＝估算器/评税惯例（见 1.17/7.1）。

## 7. 未来 fixture 的 provenance 规则

- 每条 fixture 必须含：**证据层级（T1/T2/T3）** + 官方 URL + 锚点（或已核工作纸出处） + 抓取日期 + 适用年度/文书日期 + 完整输入与输出 + 中间步骤（官方展示或**独立可复算工作纸**）。
- fixture 的**来源事实**须为 T1；T2 须先按 §0 政策晋升；T3 算术**不单独充当 fixture 来源数值**，但可作**正式 Red 期望值**（§7.1），该等期望须可审计独立复算，不因推导性质被永久禁止。
- 禁止：从待测代码、参考项目、LLM 自由文本、或本台账表格反推预期值。
- FAQ 示例按原文年度、主体与资格**整体**保留（如 Q32 的夫妻/合并事实）；示例年度假设（如 example2425 的 YA2023/24、PAM39 Q1 的 2025-10-01 起 6 个月）不得被省略或移植到其他年度。
- 单日生效规则先按**母法过渡条款的保留谓词与日期**判定；只有在母法按时刻区分适用（且已一手核验）时才要求文书时刻。普通文书缺时刻不构成 blocked（1.9）。
- 端点按区间归属（下开上闭）＋所选行公式后 ceil 计算；只有仍未核验的核证条件／文书链／最终取整才标记 OPEN 并分层，不得以“端点争议”泛称阻断本可计算的区间。
- 官方计算器 observed convention（1.10/1.11/1.14）可作 estimator 契约证据，但须标注“非普适法定规则”，且不得跨年度/税种外推。
- 若重用参考项目代码，保留 MIT 声明与固定 commit；仍不得用于预期值。
- 测试框架、文件位置与编号不属于本台账；由规格与测试作者定义。

### 7.1 Oracle 证据政策（2026-10-07 记录；2026-10-08 复审修订；证据政策，非规格批准）

- 官方**适用**计算器 + 税率/资格文本可作为**估算器取整**证据，不要求仅有正式法条引文；适用须同税种/年度/阶段，精确到操作单位与位置并留下调用点 trace；与法律冲突时以法律覆盖为准。
- **Gate2 之前**必须闭合公式／资格／适用性／取整，并确定独立 oracle 方法与命名测试；**不要求**为每个未来边界预先给出全部 expected 数字；Red 阶段固化边界数值、工作纸、caseID 与官方例对账。
- 基于**已核官方事实**的独立推导（含 T3 算术）可作**正式 Red 期望**（可审计、以事实/URL/版本/步骤独立复算），不因推导性质被永久禁止；**禁止**由生产/共享税务 helper 生成 oracle；Hypothesis 属性测试不能替代该独立性；**删除**旧概括「必须先有官方一手 fixture 才可作期望」。
- Seed 验证/激活契约可先于全部 payload 验证而批准，但**不**治愈未决的强制语义，也**不**允许在整类普通情境不可用时宣布最终验收。
- 固定且经审计的 reference harness 可在独立官方参数、合法性证明、frozen refs 与测试程序下自动验证未来 DATA；**不需要**人工逐 tuple 点击。
- **取整负面发现（2026-10-08，T1-现行法例文本）**：Cap.112 现行整合本无税额取整条款（`nearest` 0 命中；见 1.17）→ 最终税额取整属**估算器/评税惯例**层；须按税种/年度以官方计算器行为或指引证据闭合，不得宣称为法定规则。
- 本政策不修改已批准 PRD/AC；记录 2026-10-07 oracle 结论，并于 2026-10-08 按复审修订 Red 期望政策（§316），供 orchestrator 审计与 plan-reviewer 参考。
