# 001 — 香港税务计算 Agent：UI/UX 设计规格

Status: Approved（随 specs/001 用户 Gate2 2026-10-08 批准）
Created: 2026-10-07  
Updated: 2026-10-07  
关联：`docs/prd/001-hk-tax-agent.md`（Approved，AC-1..AC-18）；`docs/design/002-hk-tax-technical-contract.md`（Draft 技术契约，界面绑定见 §12）

> 本文件是界面设计提案，不代表规格批准或实现授权。所有税额由确定性税务引擎计算；AI 只负责引导、结构化及解释，不能决定规则或改写结果。实现须等待 SDD 评审和用户批准。

## 1. 设计方向与边界

为香港个人、夫妻及一般中小企业提供安静、清晰、可核验的工作台。中文优先，金额以港币呈现。避免金融营销页常见的渐变、收益图表、拟人机器人和庆祝动效；视觉重心放在用户确认过的事实、规则出处和可复核的计算步骤。

提案技术形态为本地 Python FastAPI + Jinja2，少量原生 JavaScript；界面不得依赖模型/API 才能填表或计算。未配置模型、未授权外发、网络失败时，结构化表单及确定性计算仍可用。默认不持久保存税务会话。前端不显示或接触模型密钥。

支持范围和期间必须从规则元数据真实呈现，不由界面推断：薪俸税、利得税、物业税、个人入息课税比较；物业、香港股票及租约普通印花税。覆盖盘点中的其他税费逐项标为“仅提供说明”或“不支持／需人工核实”，附主管机关、官方来源、核验日和适用状态。个人入息课税标明“评税选择”，不是独立税种。不得提供虚假的可计算入口。

## 2. 信息架构

顶部应用栏：产品名「香港税务计算」、全局规则状态入口、隐私状态和「清空本次资料」。主导航为「计算工作台」「税项覆盖」「规则更新」「计算记录」。页面说明结果为基于输入和规则快照的估算，不是税务局评税或专业意见。

### 计算工作台

1. **选择任务**：税种／评税比较；按任务切换年度或文书日期。直接税显示支持年度；印花税使用文书日期，不能用当前年度替代。
2. **输入与确认**：任务相关结构化表单，按主题分组，明确必填、可选、资格未知及不适用。显示「尚未确认」与「已确认」状态。AI 建议值单独标为「AI 建议，待你确认」，不得直接成为已确认输入。
3. **可选 AI 引导**：中文对话与问题提示。没有模型时折叠为静态提示，不阻断手填。每次计算前由用户确认结构化摘要。
4. **结果与依据**：确定性结果、税额组成、详细计算步骤、规则快照、来源、核验日、假设、警告及未覆盖事项。
5. **记录与输出**：计算记录仅保存于本次会话内存，加上用户主动下载的副本，不是持久财务数据库。可下载 JSON 全量记录、打开适合打印的报告、清除会话。导出不默认包括身份证号、密钥或不必要敏感字段。

### 税项覆盖

按“可计算／仅提供说明／不支持或需人工核实”分组；每行显示税项、子项支持状态、主管机关、来源链接、核验日期及适用期间。历史／撤销项目与现行项目分区。未核实信息不得包装成权威结论。

### 规则更新

总览显示上次尝试、上次成功、下次计划、当前不可变规则版本及总体检查状态；逐个官方来源列状态。提供「立即检查」及检查历史。候选变化显示差异、适用期间、来源证据、验证证据和受影响税项；提案、冲突、解析失败、验证失败或证据不足均明确隔离并阻止发布。已验证候选自动发布后显示独立发布记录。历史版本回滚必须二次确认并说明：回滚用于恢复运行，不代表旧规则仍然有效；受新规则影响期间可能暂停计算。不得把“检查成功”写成“规则已更新”。

## 3. 桌面工作台：1280px 线框与层级

页面最大内容宽约 1200px，居中并留至少 40px 边距。顶栏高 64px，底部细边框。标题区左对齐，显示任务标题与一句说明；右侧显示规则版本状态徽标。

工作区采用 12 栏不对称布局：左侧表单约 7 栏（760px），右侧约 5 栏（400px），间距 24px。右栏上方为 AI 对话卡片，下方为计算状态／摘要；结果出现后摘要卡替换为结果入口，不挤压输入。表单每个主题使用有标题和简短帮助文字的分组卡片，内部单栏纵向排列，避免密集仪表板。

```text
┌ 香港税务计算 ─ 计算工作台 / 覆盖范围 / 规则更新 ─ 规则 v… ┐
│ 薪俸税估算                         [规则状态：已核实]       │
│ 估算仅依据你确认的资料和所示规则版本。                      │
├───────────────────────────────────┬───────────────────────┤
│ 01 选择税项与期间                  │ AI 引导（可选）        │
│ [薪俸税 ▾] [2025/26 ▾]             │ 本地表单无需 AI。       │
│                                   │ 对话 / 建议 / 发送预览  │
│ 02 收入                            ├───────────────────────┤
│ 应课税收入 [____________] 港元      │ 计算状态               │
│ …标签、帮助、字段级错误…             │ 尚未计算 / 结果摘要      │
│ 03 家庭及资格                      │                       │
│ …                                  │                       │
│ [检查资料] [确认并计算]             │                       │
├───────────────────────────────────┴───────────────────────┤
│ 结果：最终税款 / 暂缴税 / 结欠或退款（分项、不可混算）        │
│ 计算步骤 ▾ 规则与来源 ▾ 警告 ▾ [下载 JSON] [打印报告]        │
└───────────────────────────────────────────────────────────┘
```

结果区在计算后成为主要视觉焦点，但不使用绿色大数字暗示收益。先展示状态及总览，再逐项展示最终税款、年度宽减、已缴暂缴税抵扣、下年度暂缴税估算、结欠／退款估算；缺少依据的项目显示“未能估算”，不能用零填补。所有金额都有明确标签与币种。

## 4. 移动布局：375px

单栏自然流式布局，左右内边距 16px，禁止核心流程依赖横向滚动。顶栏保留产品名与可访问菜单按钮；主导航改为可换行/菜单形式。任务选择、表单、AI、结果依次堆叠。AI 区域可折叠，默认不抢占首屏；填表和本地计算仍易找到。表单输入宽度 100%，按钮可全宽，主要操作触控高度至少 44px。表格型覆盖清单改为逐项卡片，字段标签与状态不能靠横向表格浏览。长来源链接折行；公式可换行或采用清晰的逐步列表。

```text
┌ 香港税务计算                 [菜单] ┐
│ 薪俸税估算                         │
│ [税项 ▾] [年度 ▾]                  │
│ 收入                               │
│ 应课税收入                         │
│ [____________________] 港元        │
│ …字段与错误…                       │
│ [确认并计算]                       │
│ [AI 引导（可选）⌄]                 │
│ 结果与明细（计算后出现）             │
└───────────────────────────────────┘
```

## 5. 视觉系统

### 色彩

以暖白、墨色和深青绿建立克制的专业感；暖铜色仅用于需要注意的中性提示。状态始终同时有文字和图标/形状，不单靠颜色。

| Token | 值 | 用途 |
| --- | --- | --- |
| `canvas` | `#F5F3EE` | 页面底色，柔和纸感 |
| `surface` | `#FFFFFF` | 表单、结果卡片 |
| `ink` | `#202B2A` | 主文字、标题 |
| `muted` | `#596663` | 次要说明（需满足对比度） |
| `line` | `#D9DED8` | 分隔线、输入框边界 |
| `accent` | `#176B5B` | 主按钮、链接、当前导航 |
| `accent-strong` | `#105346` | hover/active |
| `notice` | `#80551C` | 待核实／注意提示，配图标与说明 |
| `danger` | `#A83232` | 错误文字与边框，配错误图标 |
| `focus` | `#175FCC` | 键盘焦点外框 |

### 字体、间距与形状

中文采用系统 CJK 字体栈，避免下载字体依赖或字符缺字：`"Noto Sans CJK TC", "PingFang TC", "Microsoft JhengHei", sans-serif`；金额及版本号使用等宽数字特性（若可用），保证逐位对齐。正文 16px / 1.65，辅助文字不低于 14px；页面标题 28px / 1.3，分组标题 19px / 1.4，字段标签 15px。避免细字重和全大写装饰。

基础间距按 4px 倍数：4、8、12、16、24、32、48、64px。卡片内边距桌面 24px、手机 16px；卡片圆角 8px，输入框 6px；阴影极轻，仅用于浮层，层级主要由底色与边线体现。按钮实心深青绿表示主动作，次动作描边；危险操作不与普通按钮并列成主色。

## 6. 表单、确认与结果交互

- 每个控件有可见中文标签，必要时补充单位、例子及适用条件；占位文字不能代替标签。数值输入不强迫使用千位逗号；清楚区分金额、百分比、日期和负值允许情况。
- 资格字段提供明确选项，例如「符合」「不符合」「不确定」，不把未知默认为符合。依赖资格的字段随选择显示，保留已输入值但标明需确认，不静默丢弃。
- 点击「检查资料」聚焦首个问题，并在顶部显示摘要，如「还有 2 项资料需要确认」。每项在字段旁说明具体原因和修正方法，错误摘要链接到字段。错误示例：「请填写文书日期；系统不会以今天的日期代替。」
- 确认步骤显示税项、期间、输入摘要、未知／不支持项目和所用规则版本；按钮写「确认资料并计算」。用户编辑任何影响计算的资料，当前工作区结果标记「输入已更改，结果已失效」，隐藏其作为当前评估的确定税额直到重新确认和计算；已完成历史记录保留并可从记录中查阅。
- 部分可确认时只展示有依据的部分，并清楚标注「部分结果」及未完成项；范围外、期间不支持、来源状态不能确认或受待验证新规影响时显示拒算状态及理由，不显示貌似完整金额。
- AI 回复中的税额、来源和结论必须引用已计算结果；自由文本建议不带权威结果样式。对话不能取代输入确认。

### 结果内容顺序

1. 状态徽标：`估算完成`、`部分结果`、`需要补充资料`、`暂不可计算`之一。
2. 主结果与期间、港币单位、规则版本；对比任务并列显示各合法选项及差额，注明并非资格裁定。
3. 税款拆分：最终税款、宽减、已缴暂缴税、下年度暂缴税估算、结欠／退款估算分别列出；未知则标「未能估算」及原因。
4. 展开「计算步骤」：每个计税基数、适用税率、扣除／免税额、法定取整及中间结果。
5. 「规则与来源」：版本 ID、规则适用期间、核验日期、来源名称及链接；「警告与未覆盖」明确未知资格、假设和人工核实事项。
6. JSON 与打印报告操作。打印版本保留输入摘要、步骤、版本、出处、警告；不将交互控件或敏感无关字段打印进去。

## 7. AI 隐私授权

初始状态明确显示「本地计算可用；AI 未连接／未授权」。第一次可能外发时先显示确认页，不得先发送再补告知。确认页必须逐字展示接收方（供应商/配置端点的可识别名称及域名）、资料类别、将发送的**完整消息上下文及工具结果负载**，包括系统将加入的内容，而不是只列摘要。提供「返回修改」「本次允许发送」「不发送，继续本地使用」。

授权绑定当次实际字节内容及端点。内容、上下文、工具结果或接收端点任何改变，都再次预览并取得新授权；旧授权不可沿用。确认明确「只允许本次发送」，撤回后停止后续发送。密钥永不出现在预览、浏览器页面、前端存储或普通日志。用户拒绝后表单与确定性计算照常工作。

模型未配置：「AI 尚未配置。你仍可填写表格并在本机计算。」超时：「模型暂时没有回应；你的资料和计算结果未受影响。可重试，或继续使用表格。」格式／鉴权错误不展示原始响应或秘密，提供恢复提示。API 失败不得清空表单、伪造计算成功或阻止已有结果查看。

## 8. 规则更新状态与微文案

总览用明确文字标签，不以色块单独表达：

| 情境 | 标签与界面文字 |
| --- | --- |
| 正在检查 | `正在检查官方来源`；显示来源进度，不声称完成 |
| 检查完成、没有候选 | `检查已完成，未发现待处理变更`；更新时间是成功检查时间 |
| 来源部分失败 | `检查未完整完成`；逐项列出成功、失败来源及下次补查安排，不更新全局成功时间 |
| 已发现但未验证 | `发现候选变更，验证中`；列出可能影响税项／期间；阻止受影响期间无警告地使用旧规则 |
| 冲突／验证失败／证据不足 | `候选未发布，现行版本保持不变`；具体显示来源冲突、验证步骤失败或证据缺失 |
| 已验证并自动发布 | `规则已验证并发布`；分别显示检查完成时间、发布时间、版本和适用期间 |
| 无法确认当前来源状态 | `该期间暂不可计算：规则状态待核实`；提供来源与重试入口 |

调度区域展示「上次尝试」「上次成功」「下次计划检查」及逐来源时间。按日历月计划；启动首次检查或逾期合并补查，且提供「立即检查」。明确「检查成功」不等于「规则有更新」。不向官方来源检查发送任何用户税务资料。当前版本不可变；旧计算继续关联旧快照。回滚流程二次确认，说明影响期间，并明确不能因此声称过期规则有效。仅有候选、检查中或部分失败时，不给用户造成已经自动生效的错觉。

## 9. 可访问性与响应行为

- 语义化标题顺序、表单分组及按钮；所有输入使用程序关联的 label、提示与错误文本。状态更新对屏幕阅读器可感知；错误摘要可聚焦。
- 全程键盘可操作，焦点环使用高对比 `focus` 色且不被裁切；焦点顺序跟随视觉顺序。弹窗打开后焦点进入，关闭回到触发控件；Escape 可关闭非破坏性弹窗。
- 正文与控件文字满足 WCAG AA 对比度目标；错误、待核实、成功均有文本和符号，不单靠红绿区分。支持浏览器放大至 200% 而不遮挡主要操作。
- 375px 与 1280px 检查关键流程；中间宽度平滑改为单栏，不在断点间隐藏必需功能。窄屏不出现核心操作横向滚动；桌面结果可展开，但默认信息层次清晰。
- 表单提交后把焦点移到结果标题或错误摘要；加载、完成、失败均有可读状态。长计算期间仍可理解正在执行哪项任务。

## 10. 状态与场景验收映射

以下是设计可视化及交互要求，不代替产品 AC 的计算正确性测试。

| 场景 | 可见行为／文案 | PRD 映射 |
| --- | --- | --- |
| 初次打开、模型未配置 | 表单可立即操作；「AI 尚未配置。你仍可填写表格并在本机计算。」 | AC-12、AC-14 |
| 改税项或年度／文书日期 | 切换对应字段；仅列出已支持期间，范围外拒算并说明，绝不静默回退当前规则 | AC-2、AC-12 |
| 输入缺失、无效或资格未知 | 错误摘要 + 对应字段说明；没有确定税额，不把缺项当零 | AC-10、AC-12 |
| 确认后编辑收入或资格 | 当前工作区结果标为「输入已更改，结果已失效」，须重新确认并计算；已完成历史记录保留 | AC-11、AC-12、AC-13 |
| 个人入息课税比较 | 各合法方案、参与收入和差额分栏；资格不确定时说明原因，不声称最优 | AC-6、AC-12 |
| 成功与部分结果 | 分开展示最终税、宽减、已缴暂缴税、下一年暂缴税、结欠／退款；未知项目不填零 | AC-8、AC-13 |
| 结果明细及导出 | 展示输入摘要、方法、来源、核验日期、版本、警告；JSON 与打印可用 | AC-13 |
| 首次／逾期启动、每月、手动检查 | 显示尝试、成功、下次计划、当前版本；逐来源标结果且不混淆检查和发布 | AC-17 |
| 官方来源失败／部分失败 | 明示未完成来源，不伪造成功时间；无用户数据外发 | AC-17 |
| 候选冲突或验证失败 | 候选隔离、现行版本保留、受影响计算有阻断／警告；显示理由 | AC-18、AC-2 |
| 验证通过后自动发布 | 发布记录含差异、适用期、证据、版本；历史计算仍显示原快照 | AC-18、AC-13 |
| 回滚请求 | 二次确认，解释旧版本可能已失效；不把旧规则标为当前有效 | AC-18 |
| AI 外发首次／内容改变／拒绝 | 展示收件端与完整实际负载；授权只绑定当次端点和内容；拒绝后本地计算可用 | AC-14、AC-11 |
| AI 超时／限流／错误响应 | 保留输入和计算；可重试或继续本地操作，不显示伪造金额或敏感响应 | AC-14 |
| 键盘与手机操作 | 标签、错误、焦点清晰；375px 关键流程无必需横向滚动 | AC-12 |
| 覆盖范围浏览 | 可计算、说明、需人工核实明确区分；来源、主管机关、适用状态可见 | AC-1 |

## 12. 技术契约绑定（机械交接）

本节把既有界面机械绑定到 `docs/design/002-hk-tax-technical-contract.md` 的修正协议。**不改变 §3–§5 既定的布局、色彩、字体、间距、圆角、动效与微文案风格；不新增任何超出 AC-11 既有输入确认的人机关卡；不包含任何 HTML／CSS／JS／组件代码或实际测试。** 状态维持 Draft；Gate 2 批准前无 Red 测试、无生产代码。

### 12.1 权威状态与徽标绑定

- 服务器状态 `status ∈ {complete, partial, needs_input, blocked}` 一一对应 §6 既有四枚徽标：`估算完成`、`部分结果`、`需要补充资料`、`暂不可计算`。`partial` 布尔仅为派生显示字段，UI 不作权威判断。
- `blocked` 的金额字段均为 `null`（不是税额 `0`），只显示 `blocked_reason`；`partial` 只显示已知分项（见 12.4）。
- 规则法律状态（trusted_offline／proposal_not_current／related_change_uncertain／verified_future／expired／unknown）由后端经 `GET /api/v1/meta/*` 与 `GET /api/v1/update/status` 提供。**前端不解析官方页面、不自行判定旧规则有效或失效**，只按后端标签与 §8 文案渲染。

### 12.2 计算三段流程：prepare → confirm → execute

- 「检查资料」→ `POST /api/v1/calc/prepare`：校验字段，返回 PREPARED 预览（结构化摘要、`input_hash`、`input_revision`、`expected_binding={bundle_id,bundle_hash,rules_schema_version,engine_version}`）。资格缺失、资料矛盾或已知 blocked 时**不签发可执行确认能力**；界面按 §6 显示结构化问题／错误并聚焦首个问题。
- 「确认资料并计算」沿用 §6 既有确认摘要对话框（显示税项、期间、输入摘要、未知项、规则版本），不新增关卡 → `POST /api/v1/calc/confirm`（仅 UI 触发＋CSRF，`acknowledge=true`）→ 服务器签发 CONFIRMED 能力，TTL 5 分钟，绑定 `(session_epoch, input_revision, input_hash, tax_type, schema_version, execute_target, expected_binding)`。
- 执行：只可向确认能力绑定的 `execute_target` 提交；端点目标不符返回 409，且不消费能力。成功执行原子消费该能力一次。已消费后再次执行返回 409；若响应含同会话 `record_id`，定位并显示对应已完成记录，**不自动重发**，不得将该记录说成已消失或仍是当前输入结果。
- 输入字段或规则版本变更 → 仅使当前 editor 流程的 prepared／未消费确认能力失效，并撤销当前流程“结果已是当前输入与规则”的状态；需要重新确认和计算。**不删除或禁用已经完成的 session 历史 records**：每条记录固定保存确认事实与原 bundle／engine binding，可查阅、下载，并按原 binding 重放；重放仅在当前 engine version 与原 engine version 完全相等时允许，以确认事实和原 binding 重新计算，不信任或直接回显记录中保存的税额。用正常中文标示「历史估算，非当前重新评估」。迟到计算响应仅在同 `session_epoch`／`input_revision`／binding 下应用，否则丢弃，不得作为当前结果显示或导出。会话清空／过期才删除内存 records；不删除用户已下载或打印的外部副本。
- AI 工具 `propose_input`／`validate_input` 不能取得确认能力；`calculate_confirmed` 只能使用服务器保存的已确认能力。**确认能力标识不得放入任何外发模型负载。**

### 12.3 金额与输入绑定

- 金额一律以字符串提交（AmountStr），**禁止 `parseFloat` 或 JSON number**；规范形不含指数、空白、千位符与前导零。输入控件沿用 §5／§6 现有样式与 token，仅作纯文本港元输入与中文提示，不改布局。
- 类型／格式错误 → 422 字段级错误＋错误摘要聚焦首个问题，使用正常中文说明（如「请填写文书日期；系统不会以今天的日期代替。」）。

### 12.4 结果金额分项绑定

- 结果区直接使用服务器 canonical 字符串字段：`before_reduction`、`reduction`、`final_after_reduction`、`provisional_paid`、`next_provisional`、`balance`；**`balance` 正数＝结欠、负数＝估算退税**。前端不得重新相减宽减或退税重建任何金额。
- `partial` 仅含独立已知最终组件：例如缺下年度暂缴税规则时无 `balance`，该项标「未能估算」；不得把缺失输入或扣除包装成已知最终值。模型自由文本中的金额不作权威显示，权威金额仅来自服务器 canonical 记录。

### 12.5 AI 外发授权绑定

- 固定非流式 OpenAI 兼容 Chat Completions＋tools profile；密钥仅存在于服务端环境变量，**前端无密钥表单，永不接触或显示密钥**。
- 授权预览（§7 既有确认页）＝将发送的**确切完整 JSON**：system／history／tool 消息、工具结果、接收方名称与域名，全文可展开，附字节数与 SHA-256（不含 Authorization）。「本次允许发送」授予 TTL 5 分钟、单次使用授权；发送方在调用前原子消费，不重序列化。上下文、工具结果、端点、模型变化或任何重试 → 新预览＋新授权；**绝不自动补发工具结果**。
- 拒绝、停用、撤回均保留本地表单、已完成 session records 与报告；撤回仅使 outbound／pending AI 请求及迟到 AI 响应失效，不清除本地记录。撤回文案明确「停止后续发送」，不声称删除已送达供应商的资料。
- `session_epoch`（清空／过期使一切失效）与 `consent_epoch`（撤回／仅 AI 授权资料变化）相互独立：consent_epoch 变化时丢弃迟到的 AI 响应，但保留独立的本地税务结果。
- 模型错误（超时／限流／鉴权／格式）保留输入与结果，不渲染模型返回的 HTML，不显示伪造金额；按 §7 既有文案提供恢复提示。

### 12.6 会话、记录与清空绑定

- 「计算记录」＝**本次会话内存记录＋用户主动下载的副本**，不是持久财务数据库；无财务 localStorage。
- `GET /api/v1/records/{id}` 与 `/download` 均 no-store；前者供界面查阅，后者以 `Content-Disposition: attachment` 下载**全量规范确认事实**而非摘要，排除不必要的 ID／密钥字段。完成记录在本次会话中保留其原 input／bundle／engine binding；editor 输入或 rules 更新不得使其不可查、不可下载或不可按原 snapshot 重放。清空／过期删除内存记录，但不删除已下载或打印的外部副本。
- `POST /api/v1/records/replay` 仅当当前 engine version 与记录原 engine version 完全相等时，按原 bundle／binding 对确认事实重新计算；不得信任保存的税额。与「按当前规则重算」是两个不同入口，界面标签分开，不混用。
- 「清空本次资料」或会话过期 → 清除浏览器／服务端会话内存、临时对话、prepared／未消费授权、records 与挂起工作；清空另经 BroadcastChannel 通知**同会话**其他已打开标签页同步清空。提示已下载或打印的副本不会被移除。input／rules 变更只使当前 editor 流程及未消费确认失效，不删除已完成历史 records；AI 撤回只废 outbound／pending AI，不影响本地 records。

### 12.6.1 报告与下载响应

- JSON 记录下载为附件（`Content-Disposition: attachment`）且 `Cache-Control: no-store`；打印报告 HTML 以内联响应打开并同样 `no-store`，两者均不得进入持久缓存。打印／下载副本属于用户控制的外部副本，会话清空或过期不尝试删除。

### 12.7 规则更新绑定

- 「立即检查」→ `POST /api/v1/update/check`；已有作业运行时返回 **202＋现有 job_id**（幂等），前端轮询 `GET /api/v1/update/jobs/{job_id}`（响应不含财务负载）。
- 调度显示沿用 §8：上次尝试／上次成功／下次计划／当前版本。重锚规则＝最近一次**完整成功的实际完成日**＋1 个历月（月末截断），链 2026-01-31 → 2026-02-28 → 2026-03-28；**不恢复 31 日**。「检查成功」不等于「规则已更新」。
- 离线已验证快照由后端给出警告，界面照 §8 显示；`related_change_uncertain`／`expired` 只阻断对应期间与个案；`proposal`／`verified_future` 不由前端自行假设旧规则有效或失效。
- 回滚沿用现有二次确认 UI（CSRF POST）；回滚不能把已知失效日期标为当前有效，结果以后端响应为准。
- 界面不得宣称政府认证或「全税种均可计算」。
