## 1. 背景与目标

用户希望创建一个计算香港税务的 AI Agent，部分参考开源项目 `leeyc0/hksalariestax`，检查税收类型是否齐全，在计算正确的基础上提供对话及图形界面。

参考项目以薪俸税计算为主，包含家庭免税额、两种税率路径及最终税款／暂缴税计算，不能作为香港全税种覆盖的依据。其 MIT 许可允许按许可条件重用；税务规则仍须以香港主管机关及已生效法例为准。

产品目标：为个人、夫妻及一般中小企业提供可核验、可解释的主要税务估算；先保证计算正确性，再让 AI 引导用户补齐资料、调用受控计算工具及解释结果。产品不宣称替代税务局评税、专业意见或提供所有香港税项的完整计算。

## 2. 已确认的用户选择

用户通过问题工具选择：

1. **主要税种可计算**：薪俸税、利得税、物业税、个人入息课税比较及印花税；其他税费列入清单，明确边界。
2. **个人和中小企业**：个人／夫妻、独资、合伙及有限公司；优先最近已确认规则的年度，区分生效规则与预算建议。
3. **本地 Web＋可配置 API**：浏览器使用本地界面，模型接口可配置；默认不外发原始税务资料，外发前告知并获得授权，密钥不进入仓库。
4. **官方规则定期更新**：用户补充要求税率定期根据政府信息更新，并选择“验证通过后自动生效”；检查频率明确为“每月＋启动时补查＋可手动触发补查”。更新范围包括税率、免税额、扣除上限、年度宽减及适用日期，而不只是税率数字。

以下细化边界仍属于本次待批准草案，而非用户已经分别确认的事实。

## 3. 首版范围与默认边界

### 3.1 可计算的普通情境

| 项目 | 首版需求边界 |
| --- | --- |
| 薪俸税 | 普通个人及夫妻情境；用户提供应课税收入及资格资料，处理已核实的免税额、扣除、累进／标准税率比较及年度宽减。复杂福利估值或收入来源裁定不由 AI 自动完成。 |
| 利得税 | 一般法团、独资及合伙业务，以用户确认的应评税利润、适用扣除／亏损资料和税率资格计算。区分法团／非法团及符合条件的两级税率；不得把会计利润直接当应评税利润。 |
| 物业税 | 普通出租物业，区分租金收入、可扣除业主已缴差饷、法定修葺及支出免税额、不可追回租金及持有份额等已核实适用项目；不自动认定所有现金支出均可扣除。 |
| 个人入息课税 | 对符合条件的个人／夫妻，比较分别按税项评税与选择个人入息课税的结果；处理合伙份额及夫妻评税情境。它是评税选择，不是新的独立税种。 |
| 印花税 | 覆盖普通住宅／非住宅买卖或转让、香港股票普通买卖／转让、普通租约；按相关文书日期、对价／价值及必要交易事实选规则，含适用边际宽减、固定税额及取整。复杂豁免、退款、重组、提名及关联交易不自动裁定。 |

每个税种需提供细项支持矩阵：明确“支持计算”“仅提供说明”“不支持／需人工核实”。涉及未实现细项时，不得把有限功能包装为完整覆盖该税种。

### 3.2 期间与输出边界（待本次批准）

- 直接税优先覆盖 **2024/25、2025/26、2026/27**。前两年度按已确认年度规则估算最终税款；2026/27 按截至规则核验日已确认规则估算，并显著提示该年度尚未完结，不假定未来宽减或修例。
- 普通印花税交易／文书日期初始范围为 **2024-04-01 至 2026-10-07**。依 AC-17／AC-18 验证并发布后，可扩展已经核实的日期范围及批准更新协议允许的年度；更早、晚于已核验范围或涉及范围外过渡安排的情境须提示不支持，不套用当前税率。
- 暂缴税作为单独估算项目，说明假设；展示最终税款、年度宽减、已缴暂缴税、下年度暂缴税估算、结欠／退款估算，不把它们混成“本年度税额”。超出已确认下年度规则时不推测暂缴税。
- 默认中文界面及中文对话，保留香港税务正式名称，金额为港币。首版不要求完整英文界面。
- 结果属于基于用户输入及规则快照的估算；不自动提交报税表或进行付款。

### 3.3 完整性盘点范围

以“香港主要法定税项及常见相关政府税费”为盘点边界，而不是所有政府收费的无限清单。除可计算项外，至少包括：

- 酒店房租税、博彩税、应课税品税、飞机乘客离境税。
- 差饷、政府地租、商业登记费及征费；明确主管机关及其与所得税的区别。
- 跨国企业全球最低税／香港最低补足税相关制度：核实当前官方状态，标明非首版中小企业普通税率计算范围。
- 印花税相关历史／特殊项目，包括买家印花税、额外印花税及其撤销／过渡状态，不能不看日期便显示为现行应缴税。
- 已废除的遗产税；对增值税、一般销售税、独立资本增值税等常见疑问给出官方依据及适用说明，不把“不设独立税种”解释为所有相关收入必然免税。

每项列出主管机关、官方来源、核验日期、适用期间／状态及产品支持级别；清单是覆盖审计，不等于实现承诺。

## 4. 用户故事

- 作为雇员，我希望输入收入、家庭及扣除资料，知道使用什么规则以及税额如何得出。
- 作为夫妻，我希望比较允许的评税方式，避免重复申索或被误导成一定适用合并评税。
- 作为业主，我希望分别看物业税和个人入息课税的估算差异。
- 作为独资、合伙或有限公司经营者，我希望明确主体及两级税率资格，以确认过的应评税利润估算税款。
- 作为物业、股票或租约交易参与者，我希望系统按文书日期选择印花税规则，而不是只按今天的税率计算。
- 作为普通用户，我希望通过对话逐步补齐资料，也能查看及编辑结构化表单，然后确认计算。
- 作为重视隐私的用户，我希望知道哪些资料会发送给模型，在未授权时仍能使用本地计算表单。
- 作为持续使用者，我希望系统每月检查官方税务规则，在启动时补查并可手动检查，只有验证通过的新规则才自动生效，同时知道更新状态及旧计算所用的历史规则。

## 5. 编号验收条件

### AC-1 — 税项清单与真实覆盖

Given 用户打开税种入口，When 查看覆盖范围，Then 能看到第 3.3 节各项及第 3.1 节的细项支持状态、主管机关和官方来源；个人入息课税被标为评税选择，历史／撤销项目与现行项目区分；未实现税项没有可误触发的虚假计算入口，也不会宣称“全税种均可计算”。

### AC-2 — 年度、日期及规则状态

Given 用户选择年度或交易日期，When 计算，Then 使用该期间经核实的规则版本，展示官方来源、核验日期及生效状态；预算提案不作为已生效规则，尚未完结的年度显示规则快照及相关提示；超出当前已核验支持范围、日期缺失或来源状态不能确认时明确拒算，不回退到当前年度。发现相关规则变化且尚未完成验证时，对可能受影响的计算明确标示待更新／需核实，不以旧规则输出声称符合新规定的结果。

### AC-3 — 薪俸税与扣除资格

Given 普通薪俸税所需收入、家庭和资格资料完整，When 计算，Then 处理支持矩阵内适用的免税额与扣除上限，正确比较累进及标准税率并应用该年度宽减；至少覆盖基本／已婚、子女／新生子女、受养父母／祖父母、兄弟姊妹、单亲和伤残相关免税额，以及适用的强制性 MPF 扣除。其他法定扣除逐项列出支持边界；不得用未经解释的“其他扣除总额”绕过资格、上限或互斥校验。

### AC-4 — 利得税主体与资格

Given 一般法团、独资或合伙业务提供确认过的应评税利润及资格，When 计算，Then 正确区分法团／非法团的标准税率及符合条件的两级税率，处理支持的亏损／扣除及年度宽减，并说明假设。未确认关联实体限制或税率资格时追问或拒算；不推断会计利润等于应评税利润，不把业务税额自动等同各合伙人的个人税额。

### AC-5 — 物业税

Given 普通出租物业资料完整，When 计算，Then 根据该年度官方规则处理租金、可扣除差饷、法定修葺及支出免税额、已确认不可追回租金及份额等支持项目，展示计税基数和税額；不得错误扣除全部维修／利息支出或直接套用只适用于其他税项的年度宽减。

### AC-6 — 个人入息课税及夫妻比较

Given 个人／夫妻具有相关薪俸、物业或业务收入及足够资格资料，When 请求比较，Then 只比较依法可选的评税方式，展示参与收入、扣除、免税额、宽减及比较结论；考虑合伙收入份额，阻止受养人或扣除重复申索。不符合或无法确认选择资格时说明原因，不输出确定的“最优方案”。

### AC-7 — 印花税分项及日期边界

Given 支持期间内的普通住宅／非住宅交易、香港股票交易或租约资料完整，When 计算，Then 各子类型均能按文书日期、正确计税基数、适用税率／税额、边际宽减及法定取整得到可核对结果，说明应缴组成及责任假设。旧制度、特殊豁免、退款或转让安排无法核实时明确提示，不能仅凭一张物业税率表声称完整印花税覆盖。

### AC-8 — 最终税与暂缴税分开

Given 用户请求缴款估算并提供已缴暂缴税等资料，When 查看结果，Then 最终税款、宽减、已缴税抵扣、下年度暂缴税估算及结欠／退款分别标示；宽减不被错误应用到暂缴税。缺少资料或下一年度规则时，仅提供可以确认的部分，不显示伪精确缴款总额。

### AC-9 — 确定性与金额精度

Given 相同的合法结构化输入和规则版本，When 经表单、AI 工具调用或重复计算，Then 获得完全相同的税额与计算明细，且与独立核实的预期值一致；金额运算及每项法定取整不产生浮点误差、错误负税额或累积差异。LLM 的自由文本、模型更换和提示注入不能修改规则或税额。

### AC-10 — 缺失资料及异常输入

Given 缺失关键输入、无效金额／日期、矛盾家庭资料、重复申索、资格不明或范围外复杂个案，When 请求计算，Then 指出具体问题并要求补充、纠正或人工核实；不得把缺失收入默认为零、把未知资格默认为符合，或输出貌似完整的税额。允许为亏损／退款等合法情境提供专门字段，不以简单禁止负数替代业务校验。

### AC-11 — AI 引导、确认和结果忠实性

Given 已配置可用模型且用户批准相应外发，When 用中文表达税务需求，Then Agent 能识别支持的税务任务，逐步追问必要信息，并让用户确认解析后的结构化输入后调用受控计算。解释的金额、年度、引用及结论与工具结果一致；用户更改收入／资格后旧结果显示失效，必须重新确认及计算。请求无来源税率或绕过规则时拒绝，不把自由文本数值当计算结果。

### AC-12 — 可交互图形界面

Given 用户在桌面或移动浏览器打开本地应用，When 选择税项、切换年度、填表、与 AI 对话及修改资料，Then 可以完成整个计算流程，清楚区分用户输入、AI 建议、已确认输入及结果；看得到加载、错误、未配置模型、未授权和不支持情境。至少在 375px 与 1280px 宽度可用，关键控件有标签及可见键盘焦点，核心操作无必须依赖横向滚动的内容。

### AC-13 — 计算明细及审计输出

Given 已完成计算，When 查看或导出结果，Then 包含税项、期间、确认过的输入摘要、规则版本、公式／步骤、税率、扣除、宽减、暂缴税假设、官方出处及未覆盖事项；用户可下载结构化计算记录并获得可打印报告。同一输入与规则快照可重现结果；不默认包含身份证号、密钥等不必要敏感信息。

### AC-14 — 隐私、密钥及 API 失败

Given 未配置模型或未授权外发，When 使用本地表单，Then 所有支持的确定性计算仍可用且不向外部模型发送税务资料。启用对话外发前展示接收方、待发送资料类别及实际内容预览，用户可拒绝／撤回；遵循最小化原则，不默认发送原始文件、身份证号或完整财务记录。密钥不提交仓库、不写入普通日志、不提供给浏览器；默认不持久保存税务会话，用户可清空会话。鉴权失败、限流、超时、恶意或格式错误响应不暴露敏感数据、不破坏计算或伪造结果，并说明如何恢复。

### AC-15 — 正确性证据与验收门禁

Given 候选实现完成，When 验收，Then 对每个支持税项／年度具备官方示例或可独立复核的预期值测试，覆盖零值、税率／免税额／扣除上限临界值、跨年度或生效日期边界、夫妻／实体／资格区别、宽减、暂缴税和拒算路径；预期值不得从待测代码或未经核验的参考项目自动生成。完整自动化套件实际运行通过，所有变更追踪到获批准的 REQ，并由 `@acceptor` 返回 `ACCEPTED` 后才声明实现完成。

### AC-16 — 运行说明、来源与开源义务

Given 用户按仓库运行说明配置环境，When 启动应用，Then 能在本地浏览器使用，并能按说明配置／禁用模型，无需提交任何真实密钥；说明支持期间、规则维护办法、覆盖限制及税务估算免责声明。重用参考项目代码时保留 MIT 版权及许可声明并记录来源／版本，其他依赖遵循各自许可证；不宣称税务局认证。

### AC-17 — 每月官方检查、启动补查与手动检查

Given 应用已经初始化，When 距最后成功检查满一个日历月、运行中到达检查时间、首次启动或启动发现检查已到期，Then 从所支持税项的官方来源检查税率、免税额、扣除上限、宽减及生效日期；停机期间不承诺持续运行，启动时合并补查，不重复执行所有错过的任务。用户可手动触发相同检查流程；界面显示上次尝试、上次成功、下次计划、当前版本及检查／更新结果。失败或部分来源不可用不伪造“成功”时间，提示未完成核验的税项；官方检查不发送用户税务资料，亦不依赖模型 API 是否可用。

### AC-18 — 经验证自动发布、版本保留与失败保护

Given 官方检查发现候选变化，When 处理候选规则，Then 自动生效必须同时满足：来源属于批准的官方来源集合；已核实立法／实施状态及适用期间；不存在未解决来源冲突；符合已批准的更新结构和语义约束；使用独立核实的官方示例或参考证据完成候选参数及金额校验；受影响计算的边界、日期和回归测试通过。验证不得仅以 LLM 判断、待测计算代码自生成预期值或与旧值不同作为依据。通过后无需逐次人工发布确认即可启用适用版本，并记录来源快照、差异、验证证据、检查和发布时间；未来生效规则只能作用于对应期间。发布不可产生部分新旧参数混用，并发计算须固定同一版本。

任何提案、冲突、解析失败、校验／测试失败或所需证据不足均阻止该候选发布，保留最后可用版本并明确告警；已发现受影响期间的新规则但尚未核实时，不给出无警示的旧规则税额。历史计算及导出记录保留原版本并可重现；提供回滚到此前验证版本的操作与记录，但回滚不把已失效的旧规则宣称为当前有效。超出批准结构的新计算逻辑、资格变化、税种／支持范围变化属于规格变更请求，必须重走受影响审批与 TDD 门禁，不能由自动更新程序修改获批准的规格、测试或生产代码。

## 6. 非目标 / 明确排除

- 首版不计算第 3.3 节仅盘点的税费，也不承诺所有政府收费均被穷尽。
- 不提供报税提交、代缴款、eTAX 集成、身份核验或专业税务法律意见。
- 不提供会计记账、审计、从原始账本自动编制利得税调整表，亦不自动裁定收入来源地、扣除资格、常设机构或争议事项。
- 不处理跨国企业最低税、跨境收入豁免及税收协定优惠、复杂集团重组、行业优惠税制、复杂资产折旧／结转规划和全球税务优化。
- 不自动处理印花税特殊豁免／退税、遗产及法院转让、重组关联交易或首版日期范围之外的历史制度。
- 不提供“万能扣除总额”绕过支持边界。未支持的普通扣除必须显式提示该个案不能得到完整税额，不得默默忽略后给出确定结果。
- 不要求原生桌面／移动客户端、在线多租户、登录系统、付费系统、完整英文界面或文件 OCR。
- 不允许未经验证直接抓取并部署新税率，不让 LLM 生成并执行税务规则代码。批准更新协议内的参数／规则数据更新须按 AC-17／AC-18 自动检查、验证及发布；改变计算逻辑、资格语义或获批准范围的变化须经过规格变更与对应门禁，不能自动绕过。
- 不保证完全断网的 AI 对话；模型不可用时应保留本地计算。规则出处的历史快照应支持复核，不以实时网络可用为计算前提。

## 7. 约束与风险

1. **规则权威性**：优先 IRD、现行电子法例及相应主管机关。预算公告、通过、刊宪及生效是不同状态。官方页面可能混有现行、历史例子及未更新提案字样，不能整页无区分地抓取成规则。
2. **计算与 AI 的边界**：税额必须来自受控、可测试的确定性计算；模型不可自行发明税率、写入规则或发起付款／报税。
3. **已确认案例范围**：计税基础及资格依赖真实事实。输入不足时不能拿“估算”免责声明代替追问或拒算。
4. **安全与隐私**：本地服务默认仅供本机使用；外发最小化、显式授权及密钥保护是验收条件，不是可选优化。
5. **维护性**：每月、启动补查及手动官方检查，并在严格验证后自动发布；保存适用期间、官方证据和规则版本，使后续更改不静默改变历史计算。定期检查不是保证政府已提供机器可验证的新规则，未能验证时必须如实告警。
6. **技术选型未批准**：现有仓库为空；语言、框架、模型供应商及测试框架留待 SDD 基于需求决定，不在 PRD 中强行锁定参考项目技术栈。
7. **参考项目局限**：读取的薪俸税代码包含年度参数及浮点／取整实现，不能直接证明法定资格、取整或所有输入边界正确。
