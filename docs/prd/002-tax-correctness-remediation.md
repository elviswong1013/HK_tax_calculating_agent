## 1. 背景与目标

用户先询问受养人是否影响税负、项目是否支持，再询问其他未考虑的因素，并授权按建议优先级开始。源码核查发现：规格承诺、引擎实现、API 可接受事实与网页可录入事实之间存在断层；历史测试通过不足以证明普通家庭资格已经完整覆盖。

本阶段目标：修复原需求已承诺的普通薪俸税／PA 免税额资格，接通普通夫妻薪俸税评税的输入与确认流程，并消除无已核实下一年度规则时的暂缴税回退。所得税率及取整等不属于本次更改的既有语义继续沿用已批准契约。

### 1.1 保留的任务顺序

| 顺序 | 范围 | 当前状态／依赖 |
| --- | --- | --- |
| 1 | 受养人及其他必需免税额资格、夫妻薪俸税 API／表单、暂缴税规则边界 | PRD Approved，Gate 1 已通过；SDD 编写／复审中，Gate 2 未通过 |
| 2 | 常见法定扣除：捐款、自我进修、居所贷款利息、住宅租金、VHIS、年金／可扣税自愿 MPF、辅助生育等 | 保留待办；先完成阶段 1，另行需求与规格审批 |
| 3 | PA 合法选择全集、亏损及夫妻转移、跨税项缴款／退款比较 | 保留待办；依赖前两阶段及个别法定条件核验，另行审批 |

不因本阶段缩小写入范围而取消后两阶段，也不把后续功能包装成本阶段已实现。

## 2. 本阶段范围与非目标

### 2.1 范围

- 直接税年度保持 2024/25、2025/26、2026/27；新增年度不因修复自动获支持。
- 薪俸税：基本／已婚、子女及适用出生额外额、父母／祖父母、兄弟姊妹、单亲、纳税人本人伤残及伤残受养人等原 AC-3 承诺项目。
- 夫妻薪俸税：法定条件可确定的分别／联合评税及已婚免税额，所需事实能经 API 和网页录入、校验、确认并计算。
- PA：把本阶段已支持的 Part 5 免税额正确接入已有 PA／no-PA 方案；防止同一方案内重复申索。不在本阶段实现全部夫妻 PA 选择组合或亏损转移。
- 薪俸税／PA：下一年度规则缺失时，仅输出可确认的最终税及已有组件；暂缴估算明确假设、年度和依据。
- 同步受影响的 AI 输入提案／校验、确认绑定、记录步骤、打印／导出、历史查看与回放、覆盖矩阵和版本说明。

### 2.2 非目标

- 阶段 2 的新增扣除；现有长者住宿照顾开支只处理其与父母／祖父母申索的关联和互斥。
- 阶段 3 的完整夫妻 PA 方案枚举、亏损池／结转／跨配偶转移、利得税及物业税缴款接口扩展。
- 物业税及印花税算法改动；不自动把整物业评税按产权比例折半。
- 复杂收入来源判断、住房／股份福利估值、会计利润税务调整、资格争议、税务局裁定或法定分摊程序。
- 自动报税、付款、税单生成、法律零风险保证、依赖安装、自动提交／推送或重启现有服务。

未能核实的特殊情形必须明确追问／转人工，不能用零额、默认资格或任意分摊掩盖；不能据此把已承诺的普通类别整体标为不支持。

## 3. 用户故事

- 作为有受养人的纳税人，我能如实录入决定资格的资料，看到哪些免税额获计入、被排除或尚需确认，以及原因和年度依据。
- 作为已婚纳税人，我能提供双方收入、扣除及评税选择等必要事实，而不只是把婚姻状态改为「已婚」。
- 作为 PA 使用者，我能在现有可支持方案中获得同等正确的免税额处理，而不是只有薪俸税能计算。
- 作为查看缴款估算的用户，我能分辨最终税、已缴暂缴税、下一年度估算和结欠／退款，不被未知年度的数值误导。
- 作为历史记录使用者，我仍能查看原输入、原规则与原结果；升级不能暗改旧记录或冒充旧引擎回放。

## 4. 编号验收条件

### AC-1 — 真实覆盖与阶段边界

Given 用户查看支持范围，When 使用本阶段功能，Then 逐项区分「支持计算」「缺资料待确认」「范围外需人工」，且 API、网页、聊天说明一致；不将未实现的扣除、PA 选择全集或亏损功能称为已支持／完整最优。

### AC-2 — 资格事实、未知与时间条件

Given 用户申索本阶段任一免税额，When 关键身份、关系、年龄、教育、供养、政府伤残津贴资格或申索权事实缺失／未知，Then 指明需补事实，不默认符合、不默认不符合、不输出完整确定税额；明确 false 或零与缺失不同。按对应法条的年内资格条件判断，不能一律用年度末年龄替代。复杂／未核实情形明确转人工，不声称税务局已批准。

### AC-3 — 子女资格及出生额外额

Given 子女未婚、受供养及法定年龄／全日制教育／伤残不能工作事实可确定，When 计算，Then 处理未成年、18 至未满 25 岁全日制教育、18 岁或以上伤残不能工作的适用路径；不添加一般居港条件。出生年度、适用的出生次年额外额及附表 4 上限按年度和类别核实，不跨年臆推、不把不同额外项目混成未经核实的统一上限。

### AC-4 — 父母／祖父母资格

Given 居港、关系、年内年龄、政府伤残津贴资格及供养事实可确定，When 计算，Then 区分 60 岁以上／未满 60 岁符合伤残津贴资格档和 55–59 岁档；伤残标准不错误要求实际领取津贴。基本供养的连续至少六个月同住（非足额对价）或法定现金门槛，与全年连续同住额外额分别判断。死亡年度等未核实边界不得凭假设生成确定金额。

### AC-5 — 其他原承诺免税额

Given 普通兄弟姊妹、单亲、纳税人本人伤残或伤残受养人申索资格可确定，When 计算，Then 实际计入相应年度金额；兄弟姊妹及单亲须验证主要／独力照顾等法定条件，单亲额不能按每名子女累加。伤残受养人额按资格与对应基本受养额或适用院舍扣除路径依法配合，不误设一律不能叠加。

### AC-6 — 申索权、提名与互斥

Given 同一计算方案涉及同一受养人或夫妻子女申索，When 校验及计算，Then 防止重复条目、跨人重复、父母与祖父母额／子女与兄弟姊妹额的非法并用，以及同一人父母／祖父母免税额与已获长者住宿照顾开支扣除的并用。处理非分居夫妻子女整组提名；有争议或需 Commissioner 分配的情况不擅自分摊。不把 PA 与 no-PA 两个互斥方案分别使用同一合法事实错误地当成同方案重复申索。

### AC-7 — 夫妻薪俸税与已婚免税额

Given 普通夫妻提供所需收入、MPF、婚姻／分居状态、PA 选择及其他法定评税事实，When 经正式 API 或网页请求计算，Then 字段可录入、通过校验并到达引擎；按法定条件处理分别／联合评税和已婚免税额，不仅凭「已婚」自动授额，也不因没有联合评税选择就无条件只给基本额。联合评税资格不明、缺配偶事实或不可合法选择时追问／说明，不给伪确定的最优比较。

### AC-8 — PA 免税额与两种税率基数

Given 已有 PA／no-PA 方案具备本阶段可支持的资格事实，When 比较，Then 对各合法方案正确应用本阶段免税额、申索权及互斥；不得只接受受养人 ID 却一直无法计额。Part 5 免税额降低累进税基数，不误扣薪俸税／PA 标准税率基数；既有年度宽减与取整口径不被无关重构改变。无法支持完整选择集合时明确比较范围。

### AC-9 — 未知下一年度与暂缴税假设

Given 下一年度规则缺失／未经核实，When 薪俸税或 PA 估算，Then 不回退本年度；`next_provisional=null`、结果标部分可算，并列出缺失组件及清楚说明，最终税可确定部分仍可显示。有可用下一年度规则时，用该年度规则并说明继续相同年度收入等估算假设；不得声称已模拟非全年受雇年化、收入变动申请或税务局暂缴通知。不能直接复用本年度解析出的年龄档、出生额外额等而不核对目标年度。

### AC-10 — 结果、缴款与记录一致

Given 最终税、宽减、已缴暂缴税和下一年度暂缴估算完整或缺失，When 查看网页、AI 工具结果、步骤、打印或导出，Then 各组件语义和金额一致；null 不显示为零，未知组件不拼成确定总额。本阶段未支持的完整税单缴款／退款比较不得冒称已算完。

### AC-11 — 可用界面与确认安全

Given 用户以表单或聊天提供本阶段资料，When 校验、修改并确认计算，Then 能完成受支持的实际录入流程，缺资料可定位补齐；修改后原确认失效。保持 prepare → confirm → execute、会话／CSRF、目标与版本绑定及单次消费；聊天不能越过校验、确认或单次外发授权。布局、响应式、可访问性和交互由 designer 负责，沿用既有视觉方向。

### AC-12 — 版本、历史与规则更新

Given 输入契约、税务语义或规则数据改变，When 新计算、历史查看／回放或自动更新发生，Then 用明确的版本与规则证据，不静默改写旧记录、旧输入、旧规则 binding 或导出金额。不以新引擎冒充旧版本回放；原版本不可用时明确拒绝回放并保留历史查看。新增金额／字段的来源和已批准 profile 须明确；公式、资格及 schema 改变不允许伪装成普通参数自动发布。

### AC-13 — 独立预期值与回归验收

Given SDD 已经复审及用户 Gate 2 批准，When 实施本阶段，Then test-writer 先写独立来源的 Red 用例并确认正确失败原因，执行者随后最小实现；覆盖各资格正反边界、未知事实、三年度、夫妻选项、同方案重复／跨方案复用、标准基数、缺下年规则、API／真实浏览器流程和旧记录。修订错误历史断言须映射新批准 REQ，而非为了转绿削弱测试。最后完整适用测试通过、差异及未跟踪文件审阅、来源／契约／文档同步、独立 acceptor ACCEPTED；未运行／受阻不算通过。
